# 本地 AI 视频：节点框架与控制层级

面向：已有 **Substance Designer / Unity Shader Graph** 经验；  
静帧（Qwen）相对可控，视频（Wan）随机偏大；暂不接云端。

核心结论（先定调）：

> 完整动画 = **分镜资产 + 分段生成 + 多模块约束 + 剪辑装配**  
> 不是单次文生视频，也不是只靠提示词/抽卡。

---

## 0. 用你熟悉的语言理解 ComfyUI

| Substance / Shader Graph | ComfyUI 视频图 |
|--------------------------|----------------|
| Graph 是数据流 | 节点图同样是数据流 |
| Bitmap / Height / Normal 输入 | Image / CLIP / Latent / MODEL |
| 参数暴露成滑条 | Widget（steps、CFG、strength…） |
| 先 Blockout 再 Detail | 先构图/身份/运动大框架，再补细节 |
| 输出贴图进引擎 | 输出片段进达芬奇装配 |
| 一次图扛不住最终材质 | 一次 Run 扛不住最终成片 |

**稳定产出靠「约束变多、自由度变少」**，不是提示词写得越长越好。

## 1. 主流长视频 AI 工作流（行业共性）

不论可灵/即梦还是本地 Wan，能发布的长片几乎都是同一哲学：

```text
① 故事/分镜表（镜头列表）
② 角色与场景「资产库」（定妆、三视图、场景板）
③ 每镜独立短视频（2–5s，强约束）
④ 镜头间用首尾帧/重叠/溶镜对齐
⑤ 剪辑时间线装配 + 声音
⑥ 不合格镜返工（只重做那一镜）
```

主流控制手段（从强到弱大致）：

| 层级 | 手段 | 管什么 |
|------|------|--------|
| A 结构 | 分镜表、景别、时长、机位规定 | 叙事骨架 |
| B 身份 | 定妆垫图、主体参考、IP-Adapter/Face 锁、必要时角色 LoRA | 「谁」 |
| C 构图姿势 | 首帧图、ControlNet 姿态/深度/线稿、草图 | 「站位/轮廓」 |
| D 运动 | 运动幅度、首尾帧、动作参考视频、仅允许的运动白名单 | 「怎么动」 |
| E 时间 | 短片段、插帧(RIFE)、重叠帧 | 「连贯」 |
| F 外观 | 风格 LoRA、色板、后期调色 | 「像不像美影」 |
| G 装配 | 达芬奇：剪、声、字幕、统一画幅 | 「成片」 |

提示词主要工作在 **F + 部分 D**，管不住 A–E 就会「该动的不动、不该动的乱动、脸崩」。

## 2. Wan / ComfyUI 视频图：重要模块分类

把节点当成「功能积木」，先认类，再认具体名字。

### 2.1 模型加载类（Shader 里的 Pass / 主函数入口）

| 模块 | 作用 |
|------|------|
| **Load Diffusion Model** | 视频主干网络（Wan 的「渲染内核」） |
| **Load CLIP / 文本编码器**（如 umt5） | 提示词 → 条件向量 |
| **Load VAE** | 像素 ↔ 潜空间（编解码） |
| **Load LoRA** | 在主干上叠风格/加速补丁 |

你的稳定三件套：`ti2v_5B` + `umt5_fp8` + `wan2.2_vae`。

### 2.2 条件类（Shader 的 Properties / Keywords）

| 模块 | 作用 |
|------|------|
| **CLIP Text Encode（+/-）** | 语义条件；负面是「禁止项」 |
| **Load Image（首帧）** | 图生视频的最强锚点（定妆） |
| **ImageToVideo Latent**（Wan21/22…） | 把首帧编进视频 latent，并设宽高、帧数 |
| （进阶）**首尾帧** | 起止画面双约束，减漂移 |
| （进阶）**ControlNet / 姿态** | 锁骨架/构图（有模型才接） |
| （进阶）**参考视频 / Motion** | 动作迁移（另一条产品线，如 Animate） |

### 2.3 采样与调度类（多 Pass 迭代）

| 模块 | 作用 |
|------|------|
| **ModelSampling\***（如 SD3/AuraFlow 类） | 改采样日程，影响稳定性与风格 |
| **KSampler / 专用 Sampler** | 真正「算帧」的循环；steps/CFG/denoise 在这 |
| **strength / noise_aug**（若暴露） | 相对首帧允许改多少：高→动得多易毁脸；低→冻帧 |

这是你现在「脸崩 vs 冻帧」的主旋钮区。

### 2.4 解码与封装类（Blit / Encode）

| 模块 | 作用 |
|------|------|
| **VAE Decode** | latent → 逐帧图像 |
| **Create Video / Save Video** | 帧序列 → mp4；fps/codec |
| （进阶）**插帧 RIFE 等** | 增帧变顺，不负责「演对戏」 |

### 2.5 装配类（在引擎/剪辑里，不在一次 Comfy Run）

达芬奇/PR：镜号排列、J 切/叠化、旁白、音效、调色、统一 16:9。  
**长视频的「时间轴」主要在这里，不在 Wan 一次生成里。**

## 3. 大框架 → 细节：推荐控制顺序

像 Substance 先 Shape 再 Material：

### 第 1 层：镜头框架（先写在分镜表，再进节点）

每镜只规定：

- 景别（远/中/特）  
- 机位（固定为主）  
- 时长（2–3s）  
- **允许运动白名单**（例：仅烛火）  
- 使用哪张定妆/场景板作首帧  

没有这层，节点再多也是随机漫游。

### 第 2 层：身份与构图（强约束输入）

- 首帧 = 定妆或「定妆+场景」合成静帧（先用 Qwen 把构图做对）  
- 视频阶段少改身份，多继承静帧  
- 需要多角度时：先 Qwen 出多角度静帧，再各生成短视频，而不是一段视频里转头 90°

### 第 3 层：运动（窄权限）

运动分级（稳定配方）：

| 级 | 允许 | 风险 |
|----|------|------|
| A | 烛火、烟雾、光晕 | 最低 |
| B | 衣袂、发丝微动 | 中 |
| C | 眨眼、呼吸 | 易毁脸 |
| D | 走路、转头、对手戏 | 本地 5B 高风险 |

现阶段主攻 **A，偶尔 B**。

### 第 4 层：时间连贯

- 单段 ≤ 3s（length≈49）  
- 下一镜用上一镜尾帧或同一角色定妆作首帧  
- 镜间叠化在达芬奇完成  

### 第 5 层：外观统一

- 风格靠静帧阶段的 Qwen+美术电影 LoRA  
- 视频提示词少写风格散文，多写「保持参考图」+ 运动白名单  
- 成片调色统一冷青/烛金

## 4. 「要更多节点」时加什么（按需解锁）

不要一次铺满。按痛点加：

| 痛点 | 增加的控制 |
|------|------------|
| 脸漂、狰狞 | 降 strength；缩短；禁止眨眼；必要时换更稳首帧；以后再考虑 Face 锁定类节点 |
| 完全冻帧 | 略增 motion/noise；提示词只加强**一个**物理运动（烛火） |
| 构图不稳 | 先 Qwen 重做首帧；或 ControlNet 姿态（有模型再上） |
| 动作不对 | 参考动作视频 / Wan Animate 类（另一条图，勿与 TI2V 混为一谈） |
| 不够顺 | 生成后再 RIFE 插帧 |
| 不够清 | 单帧超分或成片锐化，不做整段胡乱放大 |

**模块变多的正确原因是：每一层少一道自由度；不是图越复杂越强。**

## 5. 一张「导演级」镜头卡（建议你每镜填）

```text
镜号：
首帧文件：
景别/机位：
时长：
允许运动：
禁止运动：
正/负提示词要点：
strength/分辨率/length：
验收：脸像不像 / 允许的动有没有 / 有没有乱抖
```

这比继续空刷提示词更接近可持续生产。

## 6. 和你当前进度的衔接

已具备：

- 可控静帧（Qwen 定妆）  
- 本地 Wan2.2-5B 能出片（质量不稳）  

下一阶段学习重点（建议顺序）：

1. **分镜表驱动**（镜头卡）  
2. **ImageToVideo Latent 各参数含义**（宽高、length、与 strength 关系）  
3. **首帧静帧工作流**（用 Qwen 先把「这一镜的静帧」做对再 I2V）  
4. **达芬奇装配**  
5. 再考虑 ControlNet / 动作参考 / 插帧等进阶节点

## 7. 一句话方法论

> Shader Graph 做出好看材质，靠的是分层与约束；  
> AI 长视频做出可看镜头，靠的是 **静帧定锚 + 短段 I2V + 运动权限最小化 + 时间线装配**。
